# 09. Provenance, Lineage & Processing

## 1. Mục tiêu

Cho phép xác định tài sản được tạo từ đâu, bởi ai/công cụ nào, dùng input nào, theo phiên bản công cụ/chính sách nào, và output nào được tạo ra.

## 2. Processing record

Các trường logic đề xuất:
- `processing_id`
- `tenant_id` nếu tenant-scoped
- `initiated_by`
- `module_id`
- `tool_name` / `tool_version`
- `operation_type`
- `input_asset_version_ids`
- `parameters_ref` hoặc parameters đã được làm sạch
- `policy_version`
- `started_at`, `completed_at`
- `status`
- `output_asset_version_ids`
- `error_code` và error summary đã làm sạch
- `correlation_id` / `trace_id`
- `approval_ref` nếu có

Không lưu prompt, payload, PII hoặc secret trong provenance/logs theo mặc định. Chỉ lưu nội dung nếu có mục đích, quyền và retention rõ ràng.

## 3. Quan hệ lineage

Mô hình tối thiểu có thể biểu diễn:
- asset version **was generated by** processing activity
- processing activity **used** input asset versions
- processing activity **was associated with** user/service/tool
- output asset version **was derived from** input versions
- publication event **published** một version cụ thể

Có thể tham khảo W3C PROV nhưng không bắt buộc dùng nguyên dạng ontology nếu schema nội bộ đơn giản hơn.

## 4. Idempotency và retry

- Mỗi processing job có ID ổn định.
- Retry không được tạo nhiều output công khai không chủ đích.
- Có idempotency key phù hợp với request/job.
- Ghi nhận attempts, trạng thái cuối và compensation.
- Đầu ra từng lần thử phải được quản lý như intermediate hoặc failed artifact theo policy.

## 5. Reproducibility

Khi cần tái tạo output, lưu các thông tin cần thiết và được phép lưu:
- input version references
- tool/model version
- template/prompt version nếu phù hợp
- parameters có kiểm soát
- transformation code/version
- timestamps và policy version

Không cam kết tái tạo byte-for-byte với dịch vụ AI bên ngoài nếu nhà cung cấp không đảm bảo deterministic output.

## 6. Lineage quality checks

- Output quan trọng phải có processing record.
- Input references phải tồn tại hoặc có trạng thái archive/deleted rõ ràng.
- Không cho cross-tenant lineage nếu không có cơ chế chia sẻ được phê duyệt.
- Khi asset bị xóa, lineage record phải tuân theo retention và privacy policy.
- Có thể truy ngược output đến input trong thời gian lưu giữ đã xác định.
